## Findings

**Medium 1: a bad numeric character reference crashes with a traceback instead of being reported as UNPARSEABLE (AC 11).**
- Input: `WEBVTT\n\n00:00:01.000 --> 00:00:02.000\n<v Ann>&#1114112;</v>\n` run through `main()`.
- Output: a raw Python traceback ending `ValueError: chr() arg not in range(0x110000)`.
- `&#xD800;` crashes the same way with `UnicodeEncodeError: ... surrogates not allowed`.
- Nothing is written in either case, so there is no partial record. But the documented "UNPARSEABLE, line, reason" contract and exit code 2 are not honored.
- `&#0;` is accepted and writes a NUL byte into the record.

**Medium 2: phone redaction misses common forms and wrongly redacts some numbers (AC 9, AC 1).**
- Input utterance: `Ann: call 3175550198 or 555-0198 or 317 555 0198 x12 or +1 (317) 555-0198 or 317–555–0198`
  - Output: `call 3175550198 or 555-0198 or [REDACTED:PHONE] x12 or [REDACTED:PHONE] or 317–555–0198`
  - Missed: the unseparated 10-digit number, the 7-digit local number and the en-dash form.
- Input utterance: `Ann: ticket 123-456-7890 and +2 13 21 points`
  - Output: `ticket [REDACTED:PHONE] and [REDACTED:PHONE] points`
  - These are false positives. SKILL.md §8 says story points and ordinary numbers "are left alone", which is not true for that form.
- SKILL.md does list the forms it covers, so the redaction statement is honest. The misses are an adequacy gap, not a misstatement.

**Low:**
- **Line break inside a voice tag.** Input `<v Ann\nLee>split label</v>` produces a heading split across two lines (`### U-0001 · … · Ann` then `Lee`). read_record returns the speaker as `'Ann'`, so the round-trip loses "Lee". Real exports are unlikely to do this.
- **STYLE with a trailing space.** `STYLE ` (trailing space) is refused with "expected a timing line". It is over-strict but fails safe.
- **Inline cue tags kept.** `<c.yellow>`, `<b>` and karaoke timestamps like `<00:00:01.500>` are kept as literal text. That is defensible as verbatim, but SKILL.md §7 does not mention it.
- **Crash between the two file moves.** If the process is killed between the two moves in `write_pair`, a complete-looking record is left without its provenance file. The next run's message says to "restore the missing file from git", but on a first ingest it was never in git. This is a narrow window and not tested.
- **Evidence folder name.** The quest names the folder `attempt-001`, but the work uses `ba-attempt-001`. That matches the app's convention (`jira-attempt-001` follows the same pattern), so INFERRED: not a problem.

**Path tricks (OBSERVED, all held):**
- `--out ../evil.md`, a symlinked `--out`, upper-case names and `a.provenance.md` were all refused.
- `sub/../y.md` resolved correctly into the allowed folder.
